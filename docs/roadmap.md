# 構築計画

## 1. ホストとソースの固定

ホスト検査と専用ビルド環境を用意する。LFS 12.4のパッケージ一覧を基準に、
ソースURL、バージョン、SHA-256、パッチ、ライセンスをマニフェストに記録する。
ソースを検証してから展開する仕組みを追加する。取得したソースは保持する。
コンテナのベースも初回検証後にdigestで固定する。

## 2. クロスツールチェーン (LFS第5章)

1. Binutils 2.45 pass 1
2. GCC 15.2.0 pass 1 (GMP/MPFR/MPCを含む)
3. Linux 6.16.1 API headers
4. glibc 2.42
5. libstdc++

各工程のレシピ、ログ、成功記録を保存する。テストプログラムをクロスコンパイルし、
readelfでインタープリタと参照先を確認する。API headers用のバージョンと
最終的に起動するカーネルのバージョンは別に管理する。

## 3. 一時環境 (第6・7章)

BashやCoreutilsをクロスコンパイルし、Binutils/GCCのpass 2を構築する。
その後、専用VMでchrootし、追加ツールを構築する。ホストのルートに対する
chrootやインストールを防ぐパス検査を実装してから実行する。

## 4. 最終システム (第8・9章)

glibcとGCCを含む全基本パッケージを再構築し、公式のテストスイートを実行する。
インストール済みファイルとソースの対応を記録する。Lightnixのos-release、
ユーザー、ネットワーク、SysVinit設定を導入する。

## 5. 起動と配布 (第10・11章)

QEMU向けカーネル、rootfs、ブートローダを作成する。シリアルコンソールでの
起動、ログイン、再起動を検証してからディスクイメージを配布する。
ホストのディスクへの書き込みは行わない。

## 次の判断事項

パッケージ管理方式、リリース更新方式、実機対応範囲は未決定。
まずglibcのツールチェーン検証を最初の到達点とする。
